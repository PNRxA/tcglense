# Architecture — annotated code map

The full, annotated file-by-file map of both apps (`api/` Rust backend, `web/` Vue
frontend), plus the test organization. `CLAUDE.md` is the always-loaded core and keeps
only a skeletal version of these trees; this file is the on-demand detail — read it when
you need to know what a specific module does, where a concern lives, or how the pieces
wire together. Every path is cited the way the code cites itself; annotations are
carried near-verbatim from the audited source.

## Backend structure (`api/src/`)

```
main.rs            bootstrap: env → tracing → DB connect → migrate → AppState::new → tasks::start → build_router → serve (maintenance mode still migrates but skips tasks)
router.rs          build_router(): every route + the shared middleware stack (CORS, cache layers, body limits, baseline security headers) — kept out of main so the security tests drive the exact same router in-process; exposes both the process liveness probe (`/api/health`) and DB-backed readiness probe (`/api/ready`); `MAINTENANCE_MODE` swaps this for a drained router exposing liveness + uncached SPA config while readiness/application responses are non-cacheable 503s
tasks.rs           background startup tasks: 6h maintenance loop (prune expired refresh- + email-tokens; retain_recent on the per-IP + per-user rate limiters) + either the awaited offline dummy-catalog seed (SEED_DUMMY_DATA — which also seeds the verified `e2e@tcglense.test`/`password123` dev account; offline registration is itself completable via the returned completion token, but the seeded account keeps the e2e login/session tests independent of the registration flow) or the spawned startup/periodic card-data sync; the opt-in visual-scanner fingerprint build/import background tasks it also assembles + spawns now live in `catalog::fingerprint_tasks` (this file just re-imports them); likewise the Secret Lair drop scrape (mirror origin) / import (everyone else) loops live in `scryfall::sld_tasks`, spawned here after the fingerprint block
config.rs          Config from env (…auth vars…, MAINTENANCE_MODE, DATA_DIR, SCRYFALL_USER_AGENT, TCGCSV_USER_AGENT, MOXFIELD_USER_AGENT, RESEND_API_KEY, EMAIL_FROM, CLOUDFLARE_EMAIL_API_TOKEN, CLOUDFLARE_ACCOUNT_ID (the alternative email provider; paired, both-or-neither enforced at boot), TURNSTILE_SECRET_KEY, TURNSTILE_SITE_KEY (public; paired with the secret, both-or-neither enforced at boot), TRUST_PROXY_HEADERS, RATE_LIMIT_ENABLED, SYNC_ON_STARTUP, SYNC_INTERVAL_HOURS, SEED_DUMMY_DATA, PRICE_BACKFILL_ENABLED, PRICE_BACKFILL_DAYS, SYNC_FROM_UPSTREAM, DATASET_MIRROR_URL, MIRROR_ENABLED); signups default closed, public deployments require HTTPS + secure cookies, and public signups additionally require an email provider (Resend or Cloudflare Email Service) with a non-`resend.dev` sender + Turnstile; the no-email completion-token bypass is local-only and needs `ALLOW_INSECURE_DEV_AUTH=true`; Debug redacts secrets and credential-bearing DB/Redis URLs (but not the public site key)
datasets.rs        dataset-source seam: SyncSource resolves each provider's base URLs to either the real upstream (Scryfall/MTGJSON/TCGCSV) or a TCGLense mirror (SYNC_FROM_UPSTREAM / DATASET_MIRROR_URL); the one place the sync path knows about the mirror, imported by the three provider clients
captcha.rs         CAPTCHA verification: Captcha enum (Turnstile via the shared client + per-request timeout / Disabled when TURNSTILE_SECRET_KEY unset / test-only ExpectToken) — enum dispatch like email.rs; a missing/rejected token is a 400, checked before any account work; successful Siteverify responses must also match the configured `PUBLIC_SITE_URL` hostname and the widget's fixed `auth` action
currency.rs        display-currency domain: supported ISO codes + validation and a lazy, single-flight Frankfurter USD-rate cache (12h freshness, stale-while-one-background-refresh, hard 7d stale bound, 10s upstream timeout, 5m failure backoff); catalog prices and history remain canonical USD
client_ip.rs       resolve the client IP for rate limiting (socket-peer default; X-Forwarded-For/Forwarded only when TRUST_PROXY_HEADERS) + a ClientIp extractor; None when unresolvable (the in-process test harness) so the limiter fails open
ratelimit/         rate limiting, two flavours, split into focused submodules; mod.rs holds the module doc + the shared `pub(super)` helpers (`rate_limit_key` — IPv6 masked to its /64 — and `retry_after_from_wait` — the floored-to-whole-seconds Retry-After both arms emit) and `pub use`-re-exports the public surface (rate_limit, user_rate_limit, AuthRateLimiter, UserRateLimiter, connect_redis)
  per_ip.rs        per-IP limiting for the auth endpoints: RateLimiters (one governor keyed limiter per auth class — login/register/email-send/token) + the `rate_limit` middleware (429 + Retry-After; no-ops for non-auth paths, a disabled limiter, or an unresolvable IP) + the 4 per-IP tests
  per_user.rs      per-user limiting for the authenticated surface (issue #168): UserRateLimiters (general/import classes, keyed by the access-token user id) + the bearer_* token→user resolvers (so a `tcgl_` API key resolves to its owner) + the `user_rate_limit` middleware (skips a request with no valid bearer) + the per-user tests; both limiter sets' retain_recent bound their keyspace
  backend.rs       the optional Redis backend: the shared GCRA Lua/script (GCRA_LUA) + gcra_params/redis_gcra_check/note_redis_degraded/connect_redis + the AuthRateLimiter/UserRateLimiter wrapper enums held in AppState (run the *same* GCRA over Redis, derived from the identical governor::Quota so the two can't drift, and **fail open** to the embedded in-memory arm). Also holds the Redis parity + opt-in #[ignore] Redis-limiter integration tests (gated on TCGLENSE_TEST_REDIS_URL)
db.rs              SeaORM connect options, branched on the DATABASE_URL scheme: SQLite (WAL journal mode + cache_size=-20000 + a registered REGEXP function [sqlx `regexp` feature, for the search `/regex/` syntax], byte-identical to before) or Postgres (explicit DB_* pool sizing). Backend selected at runtime — both drivers compiled in. Also holds the `Dialect` enum (the per-request SQLite/Postgres SQL-fragment seam the search compiler + sort helper import)
state.rs           AppState { db, config: Arc<Config>, dummy_password_hash, images: Arc<ImageCache>, http: reqwest::Client, currency_rates: Arc<CurrencyRates>, imports: Arc<ImportQueue>, email: Arc<Emailer>, captcha: Arc<Captcha>, rate_limiters: Arc<RateLimiters>, user_rate_limiters: Arc<UserRateLimiters> } (cloned into handlers; `http` is the request-path provider client; `currency_rates` is the display-only USD reference-rate cache; `imports` is the background collection-import queue + per-provider rate limiters; `email` is the transactional-email sender; `captcha` is the auth CAPTCHA verifier; `rate_limiters` are the per-IP auth limiters, `user_rate_limiters` the per-user limiters for the authenticated surface); AppState::new is the one construction site, shared with the security-test harness
email.rs           outbound transactional email: Emailer enum (Resend or Cloudflare Email Service via the shared client + per-request timeout, configure one — Resend wins if both set / Disabled when no provider configured, logging the message / test-only Capture mailbox) + the registration-completion/verification/reset message builders — enum dispatch, mirroring collection_import's Provider
error.rs           AppError enum + IntoResponse → JSON { error }, correct status codes (incl. Forbidden → 403 for the unverified-email login gate, TooManyRequests → 429 for rate limiting, BadGateway → 502 for a failed upstream provider)
extract.rs         JsonBody<T>: JSON body extractor whose rejections are JSON, not text/plain
test_support.rs    shared #[cfg(test)] fixtures: test_config(), a migrated in-memory SQLite DB, canonical card/set/user/holding rows (per-test tweaks via struct-update)
security_tests/    HTTP-level security tests driving the real build_router in-process (tower oneshot) — see "Test organization" below
integration_pg.rs  opt-in Postgres integration tests (`#[cfg(test)]`, `#[ignore]` + env-gated on `TCGLENSE_TEST_POSTGRES_URL`): each carves an isolated database off the base URL, runs the real migrations, and asserts the SQL seam / branched migrations on live Postgres (migration chain + down/up, case-insensitive email index, `issue_with_cooldown` 20-way concurrency, refresh rotation, collection upsert, price snapshot, the search battery incl. unique:cards / NULLS-last set order). The Redis limiter tests live in `ratelimit/backend.rs` (same `cargo test -- --ignored` run, `TCGLENSE_TEST_REDIS_URL`)
entities/          SeaORM entities (user [incl. email_verified_at + session_version + currency], refresh_token [incl. session_version + family_id], email_token = `email_tokens`; card = `cards`, card_set = `card_sets`, ingest_state = `ingest_state`, card_price_history = `card_price_history`, collection_item = `collection_items`, collection_product_item = `collection_product_items`, collection_source = `collection_sources`, wishlist_item = `wishlist_items`, wishlist_product_item = `wishlist_product_items` [independent sealed-product holdings for both surfaces — issues #435/#364], deck = `decks`, deck_section = `deck_sections`, deck_card = `deck_cards`, deck_folder = `deck_folders` [per-user decks + Archidekt-style sections + folders — issue #363], product = `products`, product_price_history = `product_price_history`, sealed_content = `sealed_contents` [card→sealed-product membership], sealed_component = `sealed_components` [sealed-product composition / "what's in the box"], art_tag = `art_tags` + card_art_tag = `card_art_tags` [Tagger art-tag metadata + the hierarchy-expanded tag→artwork mapping behind the `art:` search filter — issue #140], life_session = `life_sessions` + life_session_player = `life_session_players` + life_event = `life_events` [the life-counter tool's tracked games, their seats and their gain/loss history; a seat's `deck_id` and its mutually exclusive alternative `commander_card_id` are both deliberately FK-less + orphan-tolerant])
collection_import/ provider-agnostic collection import/sync: mod.rs (execute_import/execute_file_import orchestration [CSV-vs-text shape dispatch + printing_rows_to_holdings set/number *and* name resolution], parse_source, ProviderContext, the incremental smart-fetch path [load_local_by_external]), smart.rs (the pure smart-sync page-absorption algorithm smart_absorb_page — the early-stop decision that lets a smart fetch stop once the recently-updated prefix is already in sync — plus its 8 unit/tokio tests; no I/O, so the whole stop algorithm is tested without the network; the two provider fetch loops call it via `super::smart_absorb_page`), types.rs (Provider enum — Archidekt/Moxfield/MythicTools, the last file-and-paste-only — + ReconcileMode incl. Smart + ProviderSettings + FetchedHolding + ImportSummary), error.rs (ImportError → AppError), reconcile.rs (provider-independent engine: aggregate/plan_reconcile/atomic apply + reconcile_smart), consolidate.rs (foil-★ variant folding, issue #209: load_foil_variant_pairs resolves star↔base cards, apply_foil_remap/consolidate_local fold an **incoming** foil printing onto its nonfoil base as foil, fold_existing_star_holdings folds an **already-held** star row onto its base + deletes it so a manual/legacy star holding can't coexist and double-count — both run before reconcile), archidekt.rs (parse collection id from URL/id, rate-limited paginated fetch [get_page] → normalized holdings; fetch_smart pages newest-updated-first with early stop; shared is_foil_finish + backoff_after), moxfield.rs (parse collection id from URL/id [base64url charset], paginated fetch on totalPages with the approved MOXFIELD_USER_AGENT + 403→"needs an approved User-Agent"; fetch_smart via sortType=lastUpdated; skips isProxy rows), csv_import.rs (sniff + parse an uploaded/pasted Archidekt, Moxfield or Mythic Tools CSV export → normalized rows; returns `None` when no header matches so the caller can fall back to text; bounded + defensive), text_list.rs (the plain-text card-line grammar `2 Sol Ring (C21) 263 *F*` shared with deck_import/parser.rs — quantity/name/printing-key/foil-marker, pure and total), rate_limit.rs (per-provider RateLimiters via ProviderLimiters: 20 req/min spacing each + back_off on 429), progress.rs (ProgressReporter: lock-free fetch-progress atomics — rows fetched + provider-reported total — behind an Arc that the fetch loop writes and the job-poll endpoint snapshots for the client's progress bar; smart sync leaves the total unset), jobs.rs (ImportQueue: background jobs, single-slot queue, status registry, provider settings, spawn_import_job). Another provider = add a Provider variant + a module
deck_import/       whole-deck import pipeline (issues #389/#399), deliberately beside collection reconcile: mod.rs enforces the 2000-row deck bound, resolves/aggregates `DeckCardRow`s, optionally files generic Mainboard rows through categorize.rs's preset front-face type buckets, and atomically inserts a new deck; archidekt.rs + moxfield.rs hold strict sibling deck-id parsers and single-object fetchers over the shared provider limiter/back-off/settings (Moxfield normalizes nested + legacy boards including signature spells); parser.rs reads Archidekt/Moxfield/Mythic Tools CSV and, over collection_import::text_list's shared line grammar, plain-text lists (sections layered on top here); types.rs holds the section-aware intermediate. Reuses collection external-id + tuple lookup, foil helpers, and ImportError mapping, never collection reconciliation
migrator/          MigratorTrait impl + one migration per file (`m20240101_0000NN_<name>.rs` — the date prefix is frozen; a new migration only increments the counter, and registers in mod.rs twice: a `mod` line + a `Box::new` entry in `migrations()`)
auth/
  secret.rs        shared opaque-secret primitives for the three credential stores: generate_secret() (32 CSPRNG bytes, hex-encoded) + sha256_hex() (the fast digest persisted in place of the plaintext) — refresh.rs/email_token.rs/api_key.rs all mint-and-hash through here (crate-private; scryfall/argon2 password hashing is elsewhere — this is for already-high-entropy secrets)
  password.rs      Argon2 hash / verify (PHC strings, random salt)
  jwt.rs           access-token Claims + encode/decode (HS256, expiry in minutes, user session_version embedded so password-reset invalidation applies immediately to already-minted access tokens)
  refresh.rs       opaque refresh-token service: issue / rotate (single-use, successor-linked reuse detection, atomic per-family rotation/reuse revocation under a per-user DB lock) / revoke_one / revoke_all / prune_expired
  email_token.rs   single-use emailed-token service (registration-completion 24h / verification 24h / password reset 1h): issue / issue_with_cooldown (60s, atomic conditional INSERT gated on rows_affected so a concurrent burst can't bypass it) / consume (atomic claim, purpose-scoped) / prune_expired — same storage design as refresh.rs, no rotation lineage
  cookie.rs        build + clear the tcglense_refresh httpOnly cookie
  api_key.rs       scoped API-key service for the public API (issue #284): issue / resolve / revoke long-lived `tcgl_`-labelled keys (32 CSPRNG bytes hex-encoded; only the SHA-256 digest is persisted, the plaintext is returned exactly once at creation and never logged; multi-use, soft `revoked_at` revocation + optional `expires_at`) — storage mirrors the refresh/email-token design
  extractor.rs     the AuthUser / WritableUser / SessionUser FromRequestParts extractors over one shared resolve_principal: the Bearer credential is either an access JWT or an API key, branched on the key's `tcgl_` label (a JWT can never start with it). AuthUser accepts a session or any valid key (reads); WritableUser accepts a session or a `read_write` key and answers a read-only key with 403 (writes); SessionUser accepts only a session JWT (key management — a key can't manage keys). A bad/expired/revoked key is 401
catalog/           game-agnostic catalog: GAMES registry + find() + refresh_all()/seed_all() + keywords/ (the per-game rules-keyword glossary — a curated static table, not a query, so it answers in full on an unsynced instance and changes only with a release: mod.rs holds the KeywordEntry/KeywordKind/MatchMode DTOs, slugify() [mirrored by keywordSlug() in web/src/lib/keywords.ts, both pinned by the same fixtures], and the LazyLock name-sorted build; mtg.rs is the ~365-row MTG table. MatchMode is the interesting field: it tells the SPA how far each *name* can be trusted inside card text — `anywhere` for distinctive jargon, `ability_line` for names that are also everyday words [Fear, Storm, Crew], `never` for rules plumbing [Tap, Destroy, Counter] that keeps its glossary page but is never linked inline) (dispatch per game to its provider / offline dummy seeder; refresh_all threads the datasets::SyncSource so each provider fetches from upstream or the mirror). For MTG, refresh_all runs the Scryfall card sync (plus its independently version-gated side datasets: card rulings and Tagger art tags), then the TCGCSV sealed-product sweep, then the MTGJSON sealed-contents ingest — in that order, so cards + products exist before their references are resolved (catalog/mod.rs:47-75)
  images.rs        ImageCache: lazy on-disk image cache/downloader (<DATA_DIR>/images/<game>/<size>/<key>.<ext>), path-sanitised, fetch-concurrency-limited; CDN_MODE bypasses disk (fetch-and-serve only, no persistence)
  ingest_state.rs  shared `ingest_state` bookkeeping for the version-gated provider syncs: load / put (a borrowed StateFields update over the row) / mark_error over the one `(game, dataset)` row, all returning `Result<_, DbErr>`. TCGCSV products [`tcgcsv::ingest`], the TCGCSV historic backfill [`tcgcsv::backfill`], and MTGJSON contents [`mtgjson::ingest`] all route their load/upsert/mark-error through here (the mechanics were byte-identical); `scryfall::ingest` keeps its own copy (it additionally redacts secrets and is reused by the dummy seeder)
  fingerprint_tasks.rs  the opt-in visual-scanner fingerprint subsystem's background tasks (extracted from `tasks.rs` to sit beside its data ops): the constants + FingerprintBuild/FingerprintImport bundles + reload_fingerprint_index/run_fingerprint_pass/spawn_fingerprint_build/spawn_fingerprint_import + the fingerprint_build/fingerprint_import assemblers. The operator build (FINGERPRINT_BUILD_ENABLED) is the one sanctioned bulk image fetch — a `small`-size hash-and-discard walk through the shared 8-way image cap, nothing persisted to disk; the self-host import pulls the prebuilt index from the dataset mirror instead. Same tasks, same spawn order as before the split
scryfall/          MTG provider (the first game) — card catalog + singles prices
  model.rs         serde structs for the Scryfall card/set/bulk-data shapes we consume
  client.rs        reqwest helpers: bulk-data catalog, /sets (paginated), streaming bulk download
  ingest.rs        refresh(): stream `default_cards` line-by-line, paper-only filter, batched upserts (update-column lists derived from the entity columns), ingest_state bookkeeping
  map.rs           pure Scryfall JSON → ActiveModel shaping, kept out of ingest so it (and its tests) stand alone
  price_history.rs snapshot_prices(): daily per-card price-history capture from the committed cards rows (also used by the dummy seeder)
  art_tags/        Tagger art-tag import (issue #140): mod.rs streams the `art_tags` bulk file (version-gated via ingest_state `(mtg, art_tags)`, taggings scoped to stored artworks, zero-row wipe guard, atomic two-table swap into `art_tags` + `card_art_tags`); expand.rs the pure hierarchy expansion — a parent tag's rows include every descendant's artworks (multi-parent memoised, cycle-safe), so `art:` needs no query-time tree walk
  foil_variants.rs enrich_foil_variant_prices(): copy each foil-★ variant's foil price onto its nonfoil base card (issue #209) so a consolidated foil holding values correctly; runs in refresh_all every tick, before the snapshot (and once at boot when the periodic sync is off)
  progress.rs      live terminal progress for the bulk import (tracing-indicatif; renders nothing when stderr isn't a TTY)
  search/          Scryfall-style query compiler: lexer.rs → parser.rs (recursive descent: and/or/-/parens/quotes/regex `/…/` → Node AST) → compile/ (one submodule per filter family → sea_orm::Condition; legality via json_extract, prints/sets via oracle_id-sibling subqueries, art tags via a correlated EXISTS probe on the ingest-expanded card_art_tags) + order:/direction:/unique: directives (parse_query); error.rs (SearchError → 422); values always parameterised. tests.rs is the compiler-regression battery (renders each parsed query's WHERE clause to inlined SQLite **and** Postgres SQL to pin the per-backend divergences: `~*`, `->>`, `IS TRUE`, `STRPOS`, `$N` placeholders)
  drops.rs         Secret Lair drop grouping over a **swappable runtime store** (`RwLock<Arc<Tables>>`), seeded from sld_drops.json at boot (reseeded from the DB-persisted snapshot when present — see sld_persist.rs) and swapped by install_snapshot() from the daily scrape/import: (game,set)→{ordered drops, collector#→drop, normalised-title→drop}; table() (→ owned `Arc<DropTable>`)/has_drops()/drop_for()/drop_by_title()/drop_by_slug()/normalize_title() + content_version()/current_json() (feed the mirror ETag + the sealed-contents version gate); install_snapshot() validates + rejects an sld-less snapshot so a broken scrape can't wipe the good table; each Drop carries its collector_numbers (the join key the SLD sealed-contents derivation resolves to cards)
  sld_drops.json   committed snapshot of Scryfall's curated Secret Lair drop titles + collector numbers — now the **seed + offline / first-boot fallback** for drops.rs's runtime store (superseded at boot by the DB-persisted snapshot when one exists; regenerate via api/scripts/gen-sld-drops.mjs; the mirror origin also refreshes it live via sld_scrape.rs)
  sld_persist.rs   DB persistence for the drop snapshot: load()/save() over a singleton `sld_drop_snapshot` row (canonical JSON + content_version + updated_at, keyed by a constant "mtg/sld" discriminator, upsert on its unique index). Its own table (migration m20240101_000054) + entity rather than a column on ingest_state — a ~58KB blob there would be pulled into every unfiltered ingest_state read (e.g. the sitemap's global last-modified query). save() is called after each successful install; load() feeds the boot reseed. content_version/updated_at also give a queryable "which snapshot is loaded, when did it last refresh"
  sld_scrape.rs    the JS scraper (gen-sld-drops.mjs) ported to Rust: fetch_snapshot_json() GETs Scryfall's /sets/sld gallery and build_snapshot_json() parses the card-grid-header blocks → the sld_drops.json shape (pure parser split out for fixture tests; NoDrops on a markup change so an empty scrape is never installed). The mirror origin's daily "fetch from source"
  sld_sync.rs      the consumer side: import_from_mirror() pulls the snapshot from a mirror's /api/mirror/scryfall/sld-drops (ETag-conditional → 304), then hands it to drops::install_snapshot (which validates before swapping). MIRROR_PREFIX matches the router
  sld_tasks.rs     the two background loops (spawned from tasks::start): spawn_sld_scrape (mirror origin, MIRROR_ENABLED) re-scrapes + installs daily; spawn_sld_import (everyone else, SLD_DROPS_IMPORT_ENABLED) imports from the mirror daily. The store is **reseeded from the DB-persisted snapshot at boot (sld_persist.rs)** before the initial_delay deferral, so a restart serves the last-good drops (and the mirror serves their ETag; a consumer 304s onto them) during the deferral instead of the committed seed; each successful scrape/import is persisted back. Last-run time + import ETag still persist in one ingest_state row (mtg, sld_drops) via catalog::ingest_state, so a restart within the interval defers the first run (initial_delay), after a long downtime runs immediately. Both fall back to the committed snapshot (no persisted row) and log-not-panic on failure
  subtypes.rs      set sub-type (card-treatment) grouping (issue #282): classify() derives each card's treatment (Borderless/Showcase/Extended Art/Full Art, priority-ordered) from its ingested print attributes, with a curated subtype_overrides.json seam for treatments the data doesn't mark (e.g. scene cards); has_subtype_condition()/sets_with_subtypes()/set_has_subtypes() back the has_subtypes gate
  subtype_overrides.json  committed (currently empty) curated (game,set,collector#)→sub-type overrides, layered over classify() — the sld_drops.json analogue for un-derivable treatments
  dummy/           seed(): deterministic offline dummy catalog (no network/images) reusing ingest's map/upsert path — catalog.rs (the fabricated sets/cards), prices.rs (the year of per-card seeded random-walk price history), products.rs (a handful of fabricated sealed products — booster boxes/bundles/decks across the dummy sets, with deterministic decimal prices — so the sealed-product routes render offline); mod.rs also seeds card→product memberships (`sealed_contents`) and a couple of product compositions (`sealed_components` — e.g. the dummy bundle's "6× Play Booster + promo + extras") so the "Sealed products" and "What's in the box" sections render offline
tcgcsv/            TCGCSV provider: sealed-product catalog + product price history + a one-time historic singles-price backfill. [TCGCSV](https://tcgcsv.com) is a free, keyless daily mirror of TCGplayer's catalog + prices; every request carries the descriptive TCGCSV_USER_AGENT (it blocks generic UAs). Wired into catalog::refresh_all after the Scryfall + before the MTGJSON sync. Structure mirrors scryfall/
  mod.rs           module glue + constants: BASE_URL, MTG_CATEGORY_ID (TCGplayer category 1 = MTG), the ingest_state DATASET keys; re-exports BackfillError + the progress SPAN_NAME
  client.rs        HTTP helpers: last_updated (fetch `last-updated.txt`, the daily version-gate timestamp), fetch_groups / fetch products + prices, and the daily price-archive download (one solid-PPMd 7z per day). base_url comes from the dataset source (upstream or mirror)
  model.rs         serde shapes for TCGCSV's groups/products/prices JSON (`{success,errors,results}` envelope) + the pure folding of price records into per-product daily prices (aggregate_prices, published_on_to_date). Consumes only productId / marketPrice / subTypeName; kept provider-generic
  classify.rs      pure classifiers, derived (not fed) and unit-tested: is_sealed (a product with a `Rarity` or `Number` extendedData entry is a single card, else sealed — per TCGCSV guidance) + classify_product_type (ordered keyword match over the product name → a small fixed snake_case vocabulary — collector_/play_/set_/draft_ display-vs-pack, prerelease, commander_deck, secret_lair, bundle, …, else "other" — powering a plain-equality filter)
  ingest.rs        refresh(): daily sweep of MTG sealed products — fetch every group, per group fetch products + prices, keep only sealed products, classify each, upsert with current market prices. Version-gated on `last-updated.txt` (ingest_state `(mtg, tcgcsv_products)`); ~100ms request spacing (a full sweep ≈900 requests). Mirrors scryfall::ingest's version-gate + batched-upsert shape; its load/upsert/mark-error bookkeeping is the shared `catalog::ingest_state` helper
  price_history.rs snapshot_prices(): the sealed-product mirror of scryfall::price_history — reads the already-committed `products` rows and upserts one `product_price_history` row per `(game, product, day)`, so the daily series stays continuous even on a version-gate-skipped tick. Idempotent on the day key
  backfill.rs      the one-time historic price backfill (opt-in, PRICE_BACKFILL_ENABLED): walk TCGCSV's daily price archives from 2024-02-08 forward, filling card_price_history (join on cards.tcgplayer_id) **and** product_price_history for the days before the app began capturing its own snapshots. Runs once (gated on an ingest_state row via the shared `catalog::ingest_state` helper — put_running/finish are thin wrappers over it), resumable per date (records the last completed archive day), and never overwrites an existing `(game, entity, date)` row (`ON CONFLICT DO NOTHING`) so a real snapshot always wins. Decodes each day's 7z via sevenz_rust2
```

### Adding a backend feature

The step-by-step recipe (entity → migration → handler → route → wire types, including
the **frozen** `m20240101_0000NN` migration-naming rule and the two-place registration
in `migrator/mod.rs`) lives in `CLAUDE.md` — always loaded, so it isn't duplicated
here. Handlers take `State(state): State<AppState>` for DB access and `AuthUser` to
require a signed-in user.

**Multi-TCG by design:** `cards`/`card_sets`/`ingest_state` carry a `game`
discriminator column; the catalog layer + routes are generic. Adding a TCG = add a
`Game` to `catalog::GAMES`, a provider module (like `scryfall/`), and one arm each
in `catalog::refresh_all` (live import) and `catalog::seed_all` (offline dummy seed).
On startup `tasks::start` spawns `catalog::refresh_all` in the background (gated by
`SYNC_ON_STARTUP`) so the server is up immediately, then re-runs it on a fixed
interval (`SYNC_INTERVAL_HOURS`, default 24 = daily) to pick up newer prices/sets;
the import streams the bulk file with bounded memory and **skips re-import when the
provider's `updated_at` is unchanged** (`ingest_state.source_updated_at`), so a tick
with no upstream change is cheap. When `SEED_DUMMY_DATA` is set, `tasks::start`
instead **awaits** `catalog::seed_all` (no network, no images) to populate a small
deterministic offline catalog and skips all syncing.

The theme is applied before Vue mounts by a tiny inline script in `index.html`
(reads the same `tcglense_theme` localStorage key) so there's no flash of the wrong
theme on load; `stores/theme.ts` then owns it reactively for the rest of the session.

**SEO / social previews:** this is a CSR SPA, so each view calls `usePageMeta()`
(`lib/seo.ts`) to set a route-specific title, description, canonical URL, Open
Graph / Twitter tags, and (card + sealed-product pages) JSON-LD `Product` +
`BreadcrumbList` data (`lib/structuredData.ts`) — picked up by
JS-executing crawlers (Googlebot) and the browser tab. A `Product` node **must** carry
`offers` (Google drops the product snippet without one of `offers`/`review`/
`aggregateRating`, and reports it as a critical Search Console issue), so the node carries the
tracked market price and is **omitted entirely** for an unpriced card/product rather than
shipped invalid; everything we can't observe — availability, condition, seller, rating,
`priceValidUntil` — stays out, guarded by a unit test. `index.html` carries a
baseline copy of those tags for crawlers that **don't** run JS (most social/link
unfurlers), so shared links still get a decent preview. Every non-card page defaults its
`og:image`/`twitter:image` to a branded 1200×630 banner (`DEFAULT_OG_IMAGE` →
`web/public/og-image.png`, a committed asset regenerated by
`web/scripts/gen-og-image.mjs` via Playwright); card pages override it with the card art.
The baseline copy in `index.html` is a root-relative path that the `seoDiscoveryFiles`
Vite plugin rewrites to an absolute `VITE_SITE_URL`. That same plugin (`vite.config.ts`)
generates the site-root discovery files from `VITE_SITE_URL` and serves them in
dev/preview too: `robots.txt` (its `Sitemap:` line points at the API's DB-backed sitemap
at `/sitemap.xml`) and `llms.txt` (the [llmstxt.org](https://llmstxt.org) agent-facing map
— a curated entry point pointing at `/api/openapi.json`, `/docs`, and the main endpoint
groups, since TCGLense is API-first). Auth + signed-in pages are `noindex` and `Disallow`ed. A sibling plugin, `tesseractAssets()`,
self-hosts the card scanner's tesseract.js OCR runtime (worker / LSTM wasm cores /
`eng.traineddata.gz`, published same-origin under `/tesseract/` from the lockfile-pinned
packages, issue #451) so no third-party-served code runs at runtime — rationale in
`docs/tradeoffs.md` §Visual card scanner.

The card-catalog + sealed-product pages are **public** (no `requiresAuth`) and read
**public** endpoints, so they use `useQuery` from vue-query directly (not the
`useAuthedQuery` wrapper, which routes through `authFetch`). Card and product images are
plain `<img :src>` pointing at the proxy URL from `cardImageUrl()`/`productImageUrl()` —
they don't go through the fetch client.

On first navigation the guard calls `auth.tryRestore()` once: it hits
`/api/auth/refresh` (the httpOnly cookie is sent automatically) to mint an access
token and hydrate the user, so a session survives a page reload. The access token
lives **only in memory** (no localStorage). The exported `authFetch` helper
transparently refreshes once on a 401 and retries, logging out if that still fails.
